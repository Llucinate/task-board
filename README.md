# Наши дела

Минимальный командный планировщик для двух партнёров: категории, задачи, выполнение и подзадачи.

## Работа

- Общие категории доступны участникам пространства, личные — только владельцу.
- Быстрое создание задачи строкой ввода, поиск, разделы «Активные» и «Выполненные».
- Правка подробностей и исполнителя, подзадачи с прогрессом.
- Настоящие аккаунты. Автор определяется серверной сессией; имя профиля меняется в настройках.
- Владелец создаёт одноразовое приглашение партнёру, срок действия 7 дней.

## Сохранение и доступ

Используется отдельное **закрытое хранилище Vercel Blob**. Чтение с `useCache: false`, запись с ETag и повтором при конфликте. Данные переживают перезапуск функций и новый деплой. При недоступном хранилище сервер возвращает ошибку и не делает вид, что задача сохранена. Временной памяти в production нет.

Это небольшая версия для нескольких участников, не универсальная система для большой организации: состояние хранится единым документом. Автоматические напоминания, проекты, роли по отдельным проектам и самостоятельное восстановление пароля пока не реализованы.

Пароли хранятся как scrypt-хеши со случайной солью. Сессии: случайные непрозрачные токены, в базе только SHA-256; HttpOnly/Secure/SameSite cookies. API проверяет доступ к категории при каждом действии, защищает изменение данных проверкой Origin и ограничивает попытки входа. Код открыт, рабочие данные закрыты.

## Развёртывание

Vercel: Other, пустая команда сборки, Output Directory `.`, Node.js 22.x. Серверные переменные:

- `BLOB_READ_WRITE_TOKEN`: токен выделенного **private** Blob store.
- `TASK_BOARD_SETUP_TOKEN`: случайный секрет первоначального создания владельца (не менее 32 случайных байтов).

Первое создание аккаунта открывается через `/#setup=<секрет>`. После создания владельца начальная ссылка больше не регистрирует пользователей; дальнейшая регистрация только по приглашению. Не добавлять секрет в репозиторий. Пароль задаёт сам пользователь. Восстановление владельца пока требует помощи администратора развёртывания.

## Проверки

`npm test`: сценарий двух аккаунтов, личные/общие категории, запрет чужих правок и раскрывающего переноса, сессии, CSRF, выполнение, подзадачи, конфликт редакторов, параллельные дополнения, сохранение между процессами.

Для локальной разработки допускается `TASK_BOARD_DATA_FILE` с путём к локальному JSON-файлу и `TASK_BOARD_SETUP_TOKEN`. Файловый режим явно запрещён на Vercel и при `NODE_ENV=production`. Тестовые данные не публикуются.
